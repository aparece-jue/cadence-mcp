# Capture24.1原生离线DRC验证

24.1安装内用户指南CAP-DRC-RUN24要求在项目管理器选择DSN，使用PCB→Design Rules Check。旧的Tools路径在本机返回No MenuID Found，未调用配置回调。此PCB菜单属于Capture原理图DRC，不表示项目包含Allegro开发。

原生菜单通过CAP-DRC-ACTION的回调取得配置。私有诊断暂时替换配置窗口启动函数，返回原生配置加DoModal=1，再在finally恢复函数；不是把“关闭配置框”当作运行证据。实际取得新DRC报告，全部原四个输出冲突检出，收到晚到结束回执，原函数和配置均恢复。仍没有可公开的MCP原生DRC执行任务。

原生流程会保存私有DSN/OPJ及备份。第一次以字节不变为条件的诊断失败保留；后续独立进程审计确认原14个定义引脚连接及电气类型保持、新报告确来自本次目标，才接受冲突检测前置能力。不能因此承诺保持所有未建模属性/图形，也不能在用户真实设计上直接运行。正式任务需要先产生隔离副本，再执行/核验，不能复用只读会话语义。诊断脚本要求私有MCP_DRC_ERROR及事先写入的expected.json，报告必须位于该副本目录且不得预先存在。

末尾ORCAP-1805仅询问是否查看日志。本轮由用户处理后原调用正常返回，无重放。官方MessageBox宏可作为下一步研究依据，但尚未实际验收。复制的旧样例OPJ还触发项目升级；实际Capture.exe版本24.1-2024，样例来自24.1安装模板。ProjectVersion历史字段不能证明17.4运行，也不能仅改版本文本来绕过转换。当前改为准备只含24.1已经保存过的DSN的新副本，尚待验证打开行为。

`tools/probe_native_menu_drc.py`是固定私有诊断，`tools/audit_native_menu_drc.py`在原生工作结束后独立核对原冲突、报告来源及保存副本。原始失败与新审计分别保留在.local，公开摘要/指纹见implementation/batch-100-evidence.json。完整V03仍需干净/故障样例、正式MCP任务生命周期及完整来源、错误分类与定位验收。

报告解析现在返回逐条findings及诊断行号、打印页/坐标；坐标单位未知，不替代DSN几何校验。byPhase沿用最后明确章节标题，phaseAttribution明确不保证原生规则分类。实际报告中无效位号位于Physical标题之后，但界面列为Electrical，因此不将章节统计作为独立电气/物理类别证明。
