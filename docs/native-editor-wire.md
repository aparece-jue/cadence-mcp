# Capture 原生编辑命令布线后端

现有 `capture_plan_wire_add` 接口增加两个配套可选参数：`guiSessionId` 和 `hostProject`。同时提供时，任务在独立输出 DSN/PCB 工程中使用固定的 `OPage → PlaceWire → EndPlace → PlaceNetAlias → EndPlace` 命令；省略两项时保留已有独立 Dbo 后端。工具总数仍为 215。

本机依据为 Capture 24.1 Tcl/Tk 手册 PDF 第 117–118、124、130、138 页。坐标通过原空白夹具和原两电阻夹具验证：接口整数 DB 坐标除以 100 后传给编辑命令。此结论只用于已验证的 24.1 运行环境，不代替其他版本兼容性验证。

## 使用与任务约束

1. 通过 `capture_gui_instances` 选择已认证实例，再用 `capture_gui_attach` 显式附着。控制宿主须保持干净，没有未决属性计划或原生任务围栏。
2. `hostProject` 是控制宿主已绑定设计的同目录、同名 OPJ，须在配置的读取根内。本轮只接受单设计 PCB 控制工程；仿真源 DSN 可以是另一份已冻结的业务输入。其他控制工程资源形式仍需单独验证。
3. 仍按原接口提供页面、线段、网络别名、完整页面引脚预期、保存后的完整导线路径，以及需要时的别名所有者网络预期。参数必须为数据；不接受 Tcl、菜单名或脚本正文。
4. apply 在任务目录复制源 DSN，创建仅引用该副本的 PCB 工程。冻结宿主 PID、实例、代次、绑定与原设计/工程指纹，领取与原生网表任务共用的宿主围栏，然后经单行 source 包装派发一次固定适配器。
5. 适配器核对输出页面，放置导线与别名，完成保存链，关闭输出工程并恢复原工程。确认原工程干净后重建桥接生命周期，使旧逻辑 GUI 会话失效。后续业务须重新发现/附着，不自动重用旧会话。
6. 验证依据包括任务号/PID 回执、进入标记、恢复宿主观察、源与原宿主文件指纹，以及独立新进程重开后的原有引脚/几何/别名检查。原生脚本、回执、输出工程、转发器证明及 DSN 均记录指纹。
7. 只允许取消尚未开始的编辑任务。已开始后不得杀死 Capture 或把转发器退出当作任务取消。未收到有效回执，或未确认恢复宿主时保留围栏；继续观察或恢复，不重复派发。
8. `capture_recover_wire_add` 只验证已生成的文件。服务重启后的 apply/recover 对已验证结果不重放。`capture_open_edit_result` 的 `kind=wire_add` 继续用于衔接输出。

## 显式层次实例与删除（batch113）

`capture_plan_wire_add` 和 `capture_plan_wire_edit` 现接受可选 `editorOccurrence`。对重复 schematic，须提供唯一的原生实例位号，例如 `halfadd_A`；适配器先枚举 mapper 并核对，再以 OPage 第三个参数打开。缺失/错误实例在打开编辑页前拒绝，干净的任务副本关闭后恢复控制宿主。未保存的部分编辑保留原任务与围栏，不自动丢弃或隐藏切回。

`capture_plan_wire_edit` 的配套 `guiSessionId`/`hostProject` 目前只用于 `operation=delete`；GUI 端点修改明确拒绝，原独立端点后端保留。原生删除按页面、旧几何与网络唯一匹配目标，再通过 SelectObjectById 选择并核对实际选择对象的 ID/类型，才执行 Delete。带别名导线必须明确 `removeAttachedAliases=true`，原生同时核对其名称/锚点。未涉及的不同网导线按页面/几何/网名冻结，新旧后端均检查；该检查不冒称已覆盖目标原网分裂后的全部身份。

- 原内部四引脚短接源/电气预期不变，新显式实例任务保存重开通过，与原正常预期比较准确两失败、两通过。旧 SetPoint 只绑定端点的行为没有被声称修复。
- 原删除网名丢失源/预期不变，旧独立结果现在被拒绝，新编辑 Delete 保持全部剩余导线/网络名。真实已连接两电阻的带别名导线删除还通过四引脚解绑检查。
- 工程关闭现在先聚焦原生工程管理器，要求 DSN 锁文件消失后才接受成功。上批 CloseProject 返回本身不足以证明关闭；旧私有工程的最终清理仍保留在集成收尾项。
- 最终完整回归 661 项，660 通过、1 项原文件符号链接权限跳过。当前215工具；缺失/错误实例、明确别名确认、重复调用及恢复均保留真实MCP证据。
