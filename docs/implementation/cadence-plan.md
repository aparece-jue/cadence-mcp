# Cadence 子模块自主实施与验收计划

日期：2026-10-23。目标：完成既定Capture/OLB/原理图/PSpice业务子模块的实现与逐项验收，最后交给用户集中评审。以[模块清单](../design/07-cadence-submodules.md)为范围依据；Allegro不包含，PDF自动交付延期，Skills/规范引擎整合暂缓。不是包装官方所有数千个方法，也不把可选扩展偷偷算为已完成。

## 官方资料依据与实现方法

先阅读安装内官方对象模型和Tcl主参考，再按类/方法读取签名、参数、返回类型及适用上下文；HTML解决方案和安装脚本辅助核对。`cadence-acceptance.json`记录资料相对路径和SHA256，不将官方全文/二进制或参考仓库受限代码纳入本仓库。旧技能/索引只作为查找辅助，不是当前验收证据。

执行链仍为统一MCP Server -> 定型Capture/PSpice业务接口 -> 独立Tcl/Dbo、已有认证bridge或PSpice子进程。按session/query/property/library/edit/hierarchy/verify/simulation拆分内部文件，支持范围通过capabilities与真实tools/list公开。没有可验证实现的接口不假装可用。

读操作绑定副本与revision；写操作先plan与前置条件、不可变摘要、幂等及持久账本，再作用于明确的副本。页面/schematic/design按官方返回状态完成保存；必须由新的独立进程重开，核对属性、几何与人工预期连接。电气参数变化需额外仿真/预期，不能以pin-net未变证明电气行为未变。修改批次出现异常后保留证据，不在不确定状态自动重放。

## 工作队列与失败后移

1. 先建立功能项/依赖/官方依据/实现/验收矩阵，再执行。已有实现保留为基线证据，在受影响能力和最终门禁回归；不重复无必要GUI操作。
2. 优先完成无阻塞依赖的项；相关功能可按最小闭环交替推进（例如自建库和简单建图支撑原生正向连接验收），不把依赖环误当成全部工作阻塞。
3. 任何验收失败记录issueId、功能ID、实际调用、预期/观察、时间、证据路径/hash与复现方法；状态改deferred，queueOrder移到当前队尾。记录失败，不改阈值伪造成功。
4. 该项依赖者标waiting_dependency；其余独立项继续。待独立项完成后，按故障证据集中修复和复测；修复后只先复测受影响项，再最终整体回归。
5. 权限不足、许可证/运行上下文不可用、GUI模态、DLL崩溃等都保留未通过状态，不能把合理诊断当作功能验收通过。仅当确需用户/外部变化且至少连续三轮无可推进工作，才将目标标为blocked并说明具体事项。

## 测试工程与证据

F01单页分压/连接正反例；F02四姿态/镜像/文字边界；F03多页/重复层次/局部同名网；F04单/多单元OLB与缓存；F05位号交换/冲突；F06故障/超时/路径；F07分压DC；F08 RC瞬态/AC；F09模型/语法/非收敛/取消；F10 DRC/仿真输入来源与最终回归。每个fixture有独立人工期望，禁止用待测观察值生成同一份期望。

公开仓库保存原创脚本、schema、人工期望、摘要和源代码；本机原生样例、副本、OUT/DAT、私有绑定与敏感日志写`.local`忽略目录。验收摘要区分mock单元测试与真实Tcl/Dbo/GUI桥接/PSpice。有DSN/OLB写入时记录源前后hash、目标保存、新进程重开及节点差异。所有输出绑定本次任务/时间/文件hash，避免旧文件冒充成功。

## 最终退出条件

所有required=true功能均实现且通过对应原生正反例/必要故障验收；无未处理failed/deferred/waiting_dependency，工具契约与能力表一致，完整回归和边界检查通过。现有文件符号链接权限待补测也必须明确处理，不能计为通过。资料与官方扩展目录明确说明未纳入支持的能力；最终评审包给出功能矩阵、验证记录、复现命令和剩余限制。未满足上述条件时目标保持active，不宣称全部完成，不自动提交推送。
