# Capture符号定义坐标与页面热点

以`capture_get_part_geometry`返回的原生页面`hotSpot`作为接线坐标。库中`hotSpot`是定义局部坐标，不能一律按局部零点旋转后直接加实例位置。该接口只认证定义实例几何，不据几何推断电气连接，也不认证字体渲染。

## 本机24.1验证到的变换

官方Tcl参考p298–300提供GetBoundingBox、GetOffsetBoundingBox和GetOffsetGraphicPoint(definingPoint)，p516提供GetDefiningPart；这些签名没有承诺下面的通用数学公式。以下是本机固定夹具中预先声明并验证的行为，不能推广到未经验证的所有符号类型/版本。

令定义边界宽高为w、h，定义点为(x,y)，实例页面位置为(Lx,Ly)。先按mirrorCode=1做x=w-x；再按rotationCode选择下表，最后加实例页面位置。

| rotationCode | 变换后局部点 |
|---|---|
| 0 | (x,y) |
| 1 | (y,w-x) |
| 2 | (w-x,h-y) |
| 3 | (h-y,x) |

这不是绕定义边界中心的一般旋转，也不是减去边界左上角再变换。非正方形的尺寸及非零边界偏移需要单独核对。方向以枚举和上表为准，避免将屏幕坐标与数学坐标下的“顺/逆时针”混用。

本轮原40×40符号八姿态符合两种候选模型；80×40偏移边界否定了中心模型。新的100×60偏移边界按事先冻结的宽高模型八姿态全部通过，独立进程重开且原生GetOffsetGraphicPoint与引脚GetOffsetHotSpot一致；真实MCP八组读取与关闭会话拒绝通过。原两组结果的宽高模型只读审计用于解释差异，不将先前失败矩阵改为成功。

实例GetBoundingBox在这些实验中仍包含旧缓存范围，不能拿它代替定义边界或自动作为图面避让框。GetOffsetBoundingBox、定义几何、引脚热点和文字渲染边界分别记录，不能相互冒充。

## 实际使用

读取实例实际hotSpot后规划接线；需要将定义图形点转换到页面时使用固定原生GetOffsetGraphicPoint，并在新进程重开后核对。变更库定义/姿态后重新读取，不缓存旧热点。完整连接仍由原生网络及独立节点表验证；PDF不参与这一过程。
