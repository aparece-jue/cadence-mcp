# PSpice 输入准备选项

`pspice_prepare`仍默认严格UTF-8和standard预算。为本机官方库中的旧字节及较大依赖闭包，提供两个显式参数：

```json
{
  "sourceCircuit": "<已授权读取根内的CIR绝对路径>",
  "inputEncoding": "preserve-bytes",
  "inputBudget": "extended"
}
```

`preserve-bytes`按UTF-8语法读取可解码文本，保留其余原始字节；不猜测原字符集、不替换或转码模型内容。无引用替换的文件逐字节保持；有引用的文件只改已记录的引用行，保留其余内容、BOM及行尾。文件名引用仍必须是有效UTF-8。NUL/二进制拒绝、越界/动态引用拒绝继续生效。

standard上限64文件/32MiB，extended上限256文件/64MiB；两者均限制单文件8MiB、深度32。清单记录选择的策略、每文件opaqueByteCount和所有来源/准备后指纹。明确的预算不等于模型或语法验收。

仿真计划绑定这些策略和不可变清单；任务重定位同样保留字节。持久记录上限256KiB、计划payload上限192KiB，均有界。兼容旧计划缺省为UTF-8/standard。原生.PROBE64作为已核查的输出指令支持。CORE模型同一行的纯数值PATH参数按磁路长度处理；文件PATH、FILE、ROM/PAL外部文件模板仍拒绝。

显式保留模式下，OUT中CP1252未定义字节若仅位于完整注释行，则在解析文本中以字节转义显示，原始OUT及指纹保持；诊断/数值等其他行出现这些字节仍拒绝。普通模式继续严格解码。

当前实测：官方默认库闭包215文件约34.5MB、1649个opaque字节可准备并逐文件核对。其包含外部文件模型模板，执行预检仍拒绝；完整默认库/原生profile AC求解未验收。独立分压器的保留字节模式原生求解完成，已有结果经MCP恢复核对2.5V、OUT/DAT归属通过，未重跑求解。不要把这份兼容性证据当作默认库闭环通过。
