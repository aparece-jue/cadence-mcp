# Capture 编辑器标题栏缓存诊断

`tools/probe_gui_titleblock_cache.py` 是本机维护工具，不增加 MCP 任意 Tcl 接口。先使用独立副本、私有 Capture.INI 和单个 Capture 实例，确认活动设计，再创建私有桥接绑定。工具核对绑定的进程、程序指纹、源指纹，以及编辑器实际配置和活动设计。

```powershell
python tools/probe_gui_titleblock_cache.py --binding <私有绑定.json> --expected-ini <私有目录/Capture.INI> --output <尚不存在的诊断目录>
```

脚本通过单行 `source` 命令文件进入现有进程，最多读取64页、4096个标题栏。输出原生实例/偏移/定义边界、dirty、标题栏字段及活动页面上下文。未显示原理图时 `GetActivePage` 的上下文错误单独记录。错误进程、配置或活动设计在对象遍历前拒绝。工具不打开项目、不激活页面、不设置边界/dirty、不保存、不创建或销毁应用拥有的 Dbo session。超时只报失败，不自动重放；原始回执可能含本机路径，应保持私有。

24.1 本机启动经验：`-i` 后应传配置目录。本轮把 Capture.INI 文件路径作为目录导致警告；将 `-i` 与目录合并成一个参数没有选中私有配置。分离参数能选中私有配置，但目录也可能被当作打开对象。因此不能只凭启动参数认定成功，必须读取 `GetIniPath` 和实际活动设计。本轮先完成启动并取消旧项目恢复，再用带进程/配置/空活动设计保护的固定脚本仅打开自建 OPJ，取得回执后加载现有桥接。此启动恢复步骤仍是诊断流程，尚未作为通用自动启动产品能力开放。

批次174：未显示页面时，9个非空标题栏全部 dirty=1、实例/定义边界为零。打开 MAIN 后，该页8个实例 dirty=0、实例边界为各自位置的单点；OTHER 未显示时仍 dirty=1。打开 OTHER 后其 dirty 也清零，仍为单点。全部定义边界仍为零；页数/页码仍0、页尺寸空，两页画面均未显示预期标题栏图形。源与副本字节不变，桥接检查正常。因此 **dirty=0 不证明边界有效或绘图成功**，C05继续未通过。
