# 兼容性验证与分阶段实施

## 1. 状态定义与当前矩阵

状态分为 documented（官方说明）、file_present（本机文件存在）、runtime_probed（命令/加载探测）、fixture_passed（特定自建工程端到端通过）、workflow_passed（整个流程及故障路径通过）。它们不是单一“支持/不支持”，每个能力保存单独证据。本次未获得任何 DSN/OLB 写入工作流通过记录。

|能力|本机 24.1 当前状态|后续最小验收|
|---|---|---|
|独立 Tcl、Dbo 扩展加载|runtime_probed|干净进程重复探测、路径/中文/位数错误分流|
|独立 DSN/OLB 读|documented + 技能历史经验，未本轮验证|新建 fixture，盘点与手工/原生输出一致|
|Dbo 写、保存、重开|未本轮验证|修改副本，新进程重开；属性、几何、节点均符合预期|
|Capture GUI bridge|源码/官方示例支持该方向，未本轮连接|外置加载、认证、PID/工程绑定、断连失效|
|原生 DRC / PDF / PSpice 输入生成|待 GUI 实测|执行真正命令、核对报告和来源页；不是仅打开配置框|
|PSpice CLI 输入检查|实际启动并产生错误日志|每 job 新目录、无残留、明确 exit 和诊断|
|PSpice CLI 成功求解|未通过；第二次超时未定位|数字节点分压 2.5 V、OUT 无未处理错误、运行归属明确|
|PSpice 引擎 Tcl|documented + DLL 存在|独立进程加载/许可证/初始化/运行/释放专项验证|
|DAT 数据访问|官方命令和实际样例存在，未运行|trace/block/复数/单位读取、与原生波形或测量比对|
|高级分析|文档与 DLL 存在；后期可选|单独许可证和 profile 测试，不由普通 A/D 结果推断|
|17.2 / 17.4|仓库 README 声明，未本轮安装实测|在对应安装和新 fixture 上复测；24.1 通过不能外推|

正式兼容记录主键：installFingerprint + product/fileVersion + tclPatchlevel + bitness + backend + featureId + fixtureVersion + standardsHash。记录命令注册、操作结果、保存重开、原生导出与图面分别通过情况。许可证只记录可用性和诊断类别，避免保存敏感服务器配置。

## 2. 自建测试工程

所有 fixture 在新的测试工作区生成或复制经许可样例；安装内示例作为只读来源。每个 fixture 有人工定义的预期结构/节点表，不能用待测代码自动生成同一套预期。

|fixture|主要断言|
|---|---|
|F01 两电阻与电源|设计/页/器件/物理脚/网名数量，空选中分支，精确位号 R1 与 R10|
|F02 姿态与文字|0/90/180/270°、镜像、真实热点、alias 锚点、文字边界；修改后连接不变|
|F03 多页/重复层次|两个相同 block 实例，occurrencePath 区分，同名局部网不误合并|
|F04 OLB 与多单元|package/unit/physical pin、异构单元、库与缓存分开验证|
|F05 位号冲突|交换 R1/R2、重复目标、跨页、多单元、注释/BOM 引用映射|
|F06 错误与恢复|缺库、非法字段、路径越界、worker 崩溃、断线、超时后恢复；禁止重复创建|
|F07 分压 DC|5 V、两个 1 kΩ，V(2)=2.5 V，绝对误差建议 ≤1e-6 V|
|F08 RC 瞬态/AC|RC 时间常数和截止频率，按固定采样/测量口径与解析值比较，建议误差 ≤1%|
|F09 PSpice 失败|缺模型、错误输入、明确许可证错误（如可受控复现）、非收敛和取消分别分类|
|F10 输出与规范|导出的页来源、可读性、PNG/PDF 人工复核、波形块/单位、规则与豁免报告|

F07/F08 的误差值是测试草案，工程负责人可按求解设置批准修改；每次保存分析参数、数值容差、测量算法和取样方式。普通连接快照不能替代原生 DRC，仿真通过不能替代实际硬件验证。

## 3. 分阶段交付

### 阶段 0：证据与契约固定（本轮完成设计基线）

产物：安装/仓库指纹、问题清单、架构、工具表、公共 schema 草案、规范模型与测试矩阵。本轮只包含少量无真实工程的探测，不宣称功能实现。

进入阶段 1 的前提：使用新项目目录，避免把源码复用许可与独立实现混淆。无需运行旧 EXE 来开发新统一服务；若选择兼容它，另行取得原 MCP 源码/schema 并建立兼容测试。

### 阶段 1：统一骨架与只读 Capture

实现 core、stdio、完整已发布工具 schema、能力清单、Dbo worker、workspace manifest、open/query/snapshot/close、jobs 和结构化错误；默认仅只读工具可用。锁定运行时和依赖版本，确认不依赖全局 PATH 的偶然状态。

验收：F01、F03 读路径；所有空结果是合法 JSON，分页完整性正确，层次重复不混淆；输入工程 hash 不变；stdout 无日志污染；进程崩溃不会拖垮 MCP。不能通过的能力不注册为可用。

### 阶段 2A：Capture 最小写入闭环

先做 set_property 和 rename_reference；提供 plan、前置校验、幂等账本、副本保存、独立重开、预期节点差异。随后扩展姿态/摆放/连线/alias/global/NC。禁止把原仓库的前缀选中和方向复位逻辑原样搬入。

验收：F01/F02/F05/F06；写入与重开一致，布局变更的预期网络差异为空，电气变更严格符合显式节点表，失败批次不会被标成全部完成。

### 阶段 2B：PSpice CLI 闭环

可在稳定的 core 之后独立推进，不等待全部 Capture 编辑。先解决本轮数字节点测试超时：使用全新 cwd、较充足且可取消的启动预算、明确 ini/库路径及许可证诊断，管理整个子进程树，确认没有等待 GUI 对话框。没有证据前不归因于许可证。

实现 prepare/run/result、引用闭包、OUT 解析及 F07/F08/F09；先支持手工 CIR，后支持 Capture 导出 artifact。每次 job 新目录，禁止读取首次运行残留 OUT 作为重试结果。

验收：F07/F08 数值通过；输入错误、许可证错误、非收敛、超时分别可解释；取消只停止自有进程；进程 exit=0 仍需有效输出/无 fatal/数值检查，反之也不能脱离引擎语义自行解释返回码。

### 阶段 3：Capture GUI 原生流程及交付

实现外置 bridge，认证、实例发现、绑定与恢复；验证原生 DRC、PDF、PSpice 输入生成。先以已打开的一次性工程手动加载，避免接触用户正在编辑的真实项目。建立 dirty 会话策略，保存不跨工程。

验收：F06/F10；两个 Capture 实例并存时不串工程；断线旧句柄不可用；DRC 报告是真实运行结果；PDF 页内容和当前副本一致，图面检查文字/网标/符号方向；生成 CIR 与原理图 pin-net 及模型映射对应。

### 阶段 4：规范、Skills 与复杂能力

接入规则解析/检查、版本 pin、报告及豁免；创建小型 Skills，仅引用当前可用工具。库/缓存、多单元、层次/总线按专门 fixture 逐项拓展。引擎 Tcl 与 DAT 读取先 capability probe 后开放；Advanced Analysis 作为可选能力，单独验收，不扩大到 Allegro。

验收：缺规则、覆盖冲突、人工待审均可解释；同一输入+profile hash 的确定性检查结果一致；F04/F10 完成后再声明相应工作流可用。

## 4. 每阶段的准入与停止条件

每个阶段交付：源码、锁定依赖、schema、fixture、预期结果、运行证据、失败案例、更新的兼容矩阵。新版本仅在变更影响的能力上回归，再按发布要求执行完整门禁，避免无依据反复测试。

遇到设计指纹变化、未知对象状态、worker 异常退出、保存/重开失败或连接差异时停止该批次；保留 before/after 与日志，不自动强行继续。阻断某能力不应影响其他只读工具。

不预估固定日程：当前两个主要不确定项是 GUI 原生流程入口与 PSpice 超时根因。先完成最小垂直闭环，再据证据估算复杂能力工作量。

## PDF 验收补充（2026-10-22）

F10 增加：默认 Print 后端；页范围/纸型/缩放/模式；逐页网络名、位号及特殊字符的可提取性与查找；目标阅读器全局搜索及选择复制。Export 图面可读但文字乱码应判失败。当前 FULLADD 的 Print 两页样例已通过图面、两种解析器文字提取及关键词查找；目标阅读器剪贴板交互、中文及复杂工程仍待验证。

## 当前执行顺序更新（2026-10-22，后续以此节为准）

用户决定跳过 PDF 自动输出；PDF 是可选交付/图面复核产物，不是连接比对或规则检查的前置步骤。保留已有打印偏好，但本轮不再推进打印机/窗口自动化。阶段编号历史保留，下面的 5 项表示从当前状态到首版可用的执行顺序，不是 5 个接口或固定天数：

|顺序|阶段与完成条件|当前状态|
|---|---|---|
|1|Dbo 几何读取和规则检查：导线交叉/重叠/正交，再补连接点解释、文字与器件避让；定位到对象与坐标|首轮已接入 MCP、原生示例通过读取；连接点和边界规则仍待实现|
|2|连接验证：人工定义预期节点表，补局部网络、跨页与重复层次 occurrence，不能仅以网名或几何相交判断连接|已有定义级 pin-net 查询；完整验证未完成|
|3|可控修改：计划/预检/幂等、只写副本、保存、新进程重开；布局操作保证预期连接不变|未实现新仓库写入闭环|
|4|PSpice：独立输入和 job，分压 DC/RC 数值验收、失败诊断、超时和结果归属|尚无成功求解记录|
|5|整合交付：规范 profile 解析与版本锁定、小型 Skills、必要的原生 DRC 接口、故障恢复及发布验收|架构设计已有，尚未完成整合|

第1项当前不是全量完成；连接点和总线语义需第2项的 fixture 支撑，分阶段迭代。详细证据见 [几何验证记录](../validation/wiring-2026-10-22.md)。原生 DRC 的有人监督 GUI 运行已验证，但认证 bridge、自动入口和 MCP 整合未完成。此前矩阵是设计初始状态，实际读路径及几何进展以 phase1 与本轮记录为准。PDF、跨版本支持、引擎 Tcl/DAT 与高级能力不阻塞首版核心闭环。

### Bridge 当前进度

最小只读认证桥接和标准 MCP 状态查询已在实际 Capture 进程通过。完整 bridge 阶段仍未完成：dirty/epoch、页/选择查询、多实例、原生 DRC、修改保存与重开、故障恢复待逐项验证。参见 [bridge 实施记录](../gui-bridge.md)。

通信与只读会话生命周期已接入并通过实际Capture的MCP验收；不再只有单次状态查询。写入租约、每类编辑的dirty epoch、保存验证和原生DRC业务接口未实现。优先以docs/gui-bridge.md的验收矩阵为准，不能将传输层可用解释为全部GUI操作完成。

### 桥接基础链路本轮验收更新

### 本机桥接专项收尾

受控进程终止、新进程恢复、真实长阻塞与迟到修改拒绝已验证；正常读写和加载重载优先走MCP/固定CLI工具。桥接基础阶段在本机单Capture支持范围内结束，双Capture并行仍不宣称支持。见 [最终验收](../validation/bridge-final-2026-10-22.md)。后续转向元件、导线、参数与原生DRC等业务模块，各自独立验收。
