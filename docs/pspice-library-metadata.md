# PSpice 库元数据查询

`pspice_inspect_library`使用本机官方`parseLib`，读取授权目录内单个`.lib`的私有副本，返回顶层模型名、模型类型/AKO引用，以及顶层子电路的有序形式端口。

```json
{"sourceLibrary":"<授权读取根内的LIB绝对路径>","pinCount":2,"offset":0,"limit":100}
```

`pinCount`标记端口数匹配的子电路，其他定义仍在结果中；`offset/limit`用于分页。结果声明`definitionScope=top_level`，另计`localDefinitionsNotReturned`。子电路内部的局部定义不会混入顶层列表。模型的nativeNodeDescription是原生描述，不能作为Capture器件物理引脚映射。

输入限单文件8MiB、子电路嵌套32层、定义100000项；只在配置安装目录加载固定DLL。含`.LIB/.INC/.INCLUDE`的文件先拒绝；先逐个检查实际依赖文件，不能靠此工具隐式扩展读取范围。NUL/非法定义名、未闭合子电路、原生失败或元数据遗漏/重复/筛选不一致均不发布结果。原始文件及快照前后hash核对，原生进程树结束后才读取结果。每次查询建立新的私有快照。

模型定义正文不出现在结果中。完整原生输出留工作区供诊断，64MiB上限；返回字段只保留元数据。该工具不运行仿真，不校验模型有效性，不完成库/AKO依赖可达性分析。

本机24.1真实MCP核验：自编4定义/AKO、2和3端口、分页、引用/参数拒绝通过；官方breakout.lib复制件75个顶层定义及32个未返回局部定义与源层次计数一致。首次将局部定义混入预期导致拒绝的报告保持，新版本明确作用域后在新工作区复验通过。完整默认nom.lib求解及模型外部文件依赖继续未通过。
