# Dbo 导线几何与 MCP 检查验证

日期：2026-10-22。PDF 自动输出按用户要求延期，不再是 MCP 检查前置步骤。

## 实施结果

新增 `capture_check_wiring(sessionId)`，在会话绑定副本上启动新的独立 Tcl/Dbo 进程，读取全部原理图定义页面上的导线多点坐标、原生 ID、对象类型值和本地网名，再进行有限几何检查。工具写入副本工作区内的原始几何 JSON 和报告 JSON；不会保存或修改 DSN，也不需要启动 Capture GUI 或生成 PDF。对外仍不提供任意脚本入口。

报告关联会话 revision、源指纹和原始几何文档 hash。对象 ID 仅在该原始几何文档/本次报告中解释，不能直接当作跨进程可写句柄；原生 ID 与页面一并用于人工定位。坐标为 Capture 原生整数单位，不声称是 mm。

规则：WIRE-CROSSING-CANDIDATE（线段内部交叉）、WIRE-T-CONTACT-CANDIDATE（端点接在线段内部）、WIRE-COLLINEAR-OVERLAP（正长度共线重叠）、WIRE-NON-ORTHOGONAL、WIRE-ZERO-LENGTH。共享端点和普通拐点不计作交叉。所有配对限制在同一页面，保留同一 polyline 的非相邻自交候选。每对线段单独报告；多线交会同一点可能产生多条候选，数量不等于唯一交点数量。

初版 profile 是代码内固定的 wire-geometry-advisory@0.1.0，尚未接入独立规范解析器。交叉和 T 接触默认提示，不能据此判定电气短路或违规。即使无候选也返回 designPassed=null、electricalConnectivityVerified=false。网名相同不被当成连接证明。

## 本机实际运行

安装 24.1；只读来源为官方 FULLADD 样例，复制到新的 `.local/wiring-stdio-20261022-r2/` 工作区。通过标准 stdio MCP 运行创建副本、打开、导线检查、分页查询、快照、新进程重复结构读取与关闭。

- 结构：2 个原理图定义、2 页、9 个器件、41 个引脚。
- 导线：28 条、28 个线段。
- 2 处几何交叉候选，坐标 (270,310)、(350,310)，均属于 schematic-1/page-1；具体 wire ID 和原生 ID 映射在原始几何 JSON 中。
- 未发现正长度共线重叠、非正交或零长度线段。这只是当前示例的几何结果，不是全设计通过。
- 安装示例源文件前后 SHA-256 相同：27c6d11ffbb8d677954d8e56eba26a4b725c677aa83a08020da682972e1ef104。
- 没有调用 GUI、Print 或 Export，也未生成 PDF。

原始材料保留在忽略的本地目录，`native-smoke-report.json` 保存报告和运行断言；`tools-list.json` 保存本次 8 工具 schema，已同步到 contracts/tools.v0.1.json。原始示例 DSN 不提交。

## 限制与失败路径

本轮尝试 PointIsJunction 时状态失败，移除了该未验证调用，没有将异常解释成无连接点。连接点、总线/Bundle 语义、重复层次 occurrence 网络、引脚连接一致性、文字与器件边界避让、栅格和原生 DRC 均未在此工具验证。后续需核实连接点迭代语义并用人工定义的 fixture 验收。

最多 2000 个非零线段、10000 条几何 finding；超过限制明确失败，不能冒充检查完成。非正交线会报告，但暂不参与交点计算；此时 geometryComplete=false，MCP envelope 为 partial。geometryComplete 仅指已实现的正交线段配对规则是否覆盖，不代表电气或全部绘图规范完整。当前为有限 O(n²) 配对，复杂工程后续需空间索引和页面范围工具。

当前单元/协议测试 32 项：31 通过，1 项因 Windows 符号链接权限跳过。新增规则测试的预期坐标由手写 fixture 独立给定，覆盖交叉、T 点、重叠、共享端点、跨页隔离、对角线降级、非法坐标与数量限制；服务测试覆盖源 revision、报告 hash、异常 worker、失效会话、严格参数和 partial 返回。

本轮只完成几何检查最小闭环，尚未完成本阶段的连接点语义、文字/器件避让等全部规则，不把示例候选数量作为真实设计的期望表。
