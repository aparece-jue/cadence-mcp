# 本机 Capture 桥接专项验收收尾

日期：2026-10-22。支持环境：Windows 当前登录会话、Capture 24.1、本机回环通信、显式绑定的测试副本。结论限定此环境和已开放的固定工具，不扩展为所有版本或一般电路编辑均已实现。

## 本次补齐并通过的专项

|验收项|实测证据与结果|
|---|---|
|真实 GUI 事件线程长阻塞|Tcl 事件线程阻塞12秒；客户端约8.047秒返回；迟到应用请求没有写入文件|
|超时后的会话处理|写入通道失联后本地会话失效，旧ID被拒绝；需显式附加新会话|
|确证没有执行的任务|新MCP服务器读取持久记录，原生回执仍为planned、generation未变、文件哈希等于修改前；退役原生计划后解除锁，不重放修改|
|受控 Capture 进程终止|终止前实时核验4个已知测试设计、34个库全部clean，核验PID、进程创建时间和可执行文件；以强制终止模拟进程崩溃，不是声称发现了原生应用崩溃缺陷|
|进程死亡后的不确定任务|持久started记录保留；死实例不再被发现；缺失原生回执时拒绝认定成功，保留锁，文件未再次变化|
|新 Capture 进程恢复工作|新PID9032、新实例、新绑定；拒绝旧进程会话；读取两页；标准stdio MCP重新完成写入、保存、独立重读与定义级连接比较|
|不依赖桌面操作的加载工具|tools/load_gui_bridge.py 在实际Capture通过重载，返回desktopActionsUsed=false；重复健康检查不必重载|
|加载兼容性|命名空间中source JSON helper、中文及Tcl特殊字符按数据处理的原生测试通过；命令行使用单行source包装，避免直接重放多行过程定义|

报告分别在 `.local/bridge-stall-20261022/`、`.local/bridge-crash-20261022/`、`.local/bridge-crash-restart-20261022/`。旧崩溃任务的锁为有意保留的故障证据，不能自动删除或因新实例可用而认定旧任务成功。

## 多实例结论的澄清

此前把“两份真实Capture并行”列为桥接必须达到的行为过于宽泛。本机普通启动和独立INI目录启动都没有得到持续运行的第二进程，打开请求会转交现有实例。Cadence社区对23.1的[相关答复](https://community.cadence.com/cadence_technology_forums/pcb-design/f/allegro-x-capture-cis/62420/unable-to-open-multiple-dsn-files-from-the-file-manager/1400815)也描述同一会话单Capture、多设计在同一实例打开；它是相关版本的支持线索，不能单独证明所有24.1安装都相同。

本次发布只验收本机单Capture模式。双真实进程并行没有通过，不宣称支持；两个独立Tcl进程的协议隔离测试保留，不用它冒充双Capture实测。切换活动工程会使绑定失效，必须重新准备并显式附加，不能暗中将旧会话转向新工程。

## GUI 使用约定

正常状态查询、页面/选择读取、计划、应用、保存和核验均走MCP，不点击菜单或手工输入命令。加载/重载优先使用：

```text
python tools/load_gui_bridge.py --binding <私有绑定目录/binding.json>
python tools/load_gui_bridge.py --binding <私有绑定目录/binding.json> --reload
```

加载器只生成固定脚本，核验PID、进程文件与工程指纹，拒绝不同活动设计，不接受MCP传入的任意Tcl。不修改安装目录或全局自动加载配置。

本次崩溃后出现了Capture自带的自动恢复工程提示，需要一次桌面取消；因此整个崩溃重启流程并非无人值守。首轮加载尝试还发现测试脚本命名遮蔽、命名空间和命令行逐行重放的问题；已修正并以加载工具复测，不将早期超时算作通过。遇到这类启动/恢复弹窗才需要桌面介入，不能承诺所有异常都免GUI。

## 测试与边界

最终65项回归测试：64通过，1项因Windows文件符号链接权限不足跳过。桥接专项均通过；该跳过项属于一般读取根的文件符号链接测试，保留原记录，另增加实际Windows目录junction越界拒绝测试并通过。未修改系统权限或开发者模式。

原生协议测试需设置CADENCE_TEST_TCLSH。已有其他验收包括认证、限额、会话代次、模态拒写、计划取消、幂等、不确定写入禁止重放、服务器重启后核验、正常保存和停止重载。

元件、导线、一般参数编辑、原生DRC和PSpice仍属后续业务模块，未因桥接收尾而变为可用。occurrence层次连接未验证，PDF继续延期。安装示例与用户真实设计的SHA-256保持不变；不自动提交或推送。
